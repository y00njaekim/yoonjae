`.wiki/`는 사용자가 반년 뒤에 다시 찾아볼 것들을 모아둔 개인 노트다.

페이지의 본체는 요약문이 아니라 **포인터**다 — 링크, 코드 위치, 관련 페이지. 산문은 그 포인터 묶음을 다시 열었을 때 방향을 잡아주는 만큼만 쓴다. 읽는 사람은 사용자 본인이다. 빠짐없이 압축해 쌓는 게 아니라, 사용자가 소화할 수 있는 수준으로 남긴다.

## 위키 찾기

cwd에서 위로 올라가며 `.wiki/`를 찾는다. 없으면 만들지 묻고, 승낙하면 빈 폴더만 만든다.

## 기록

1. **겹치는 페이지를 찾는다.** 파일명 목록을 훑고 핵심어로 `grep` 한다. 겹치는 게 있으면 `X에 붙일까요, 새로 만들까요` 묻고 답을 기다린다.
2. **주제가 여럿 섞였으면 쪼갤지 묻는다.** 기본은 한 페이지다.
3. **`status: draft` 로 저장한다.**
4. **`open <경로>` 로 열어준다.** 사용자가 보고 고칠 곳을 말한다.

`draft` 인 동안은 같이 다듬는 상태다. 이후 수정 요청은 그대로 반영하고 `updated` 를 갱신한다.

## 읽기

1. **파일명 목록을 본다.** 파일명이 한글 제목이라 여기서 대부분 걸러진다.
2. **핵심어와 그 동의어로 `grep` 한다.** 목록이 놓친 것을 잡는다.
3. `status: deprecated` 페이지는 뺀다. 사용자가 옛날 것도 보자고 하면 넣는다.
4. **근거로 쓴 파일명을 밝히고** 답한다.

목록과 `grep` 이 둘 다 비었을 때만 위키에 없다고 말한다. 찾아봤다는 사실까지 말한다 — 위키에 없다는 것도 답의 일부다.

## 페이지 형식

파일명은 한글 제목, 공백 대신 하이픈: `도면-정렬-방식.md`. `.wiki/` 안은 flat이다.

```markdown
---
created: 2026-08-12
updated: 2026-08-12
status: draft
---

(맥락 — 왜 이걸 알아봤는지, 무슨 얘기 끝에 나온 건지. 형식 규칙 없이 자유롭게)

## 포인터
- [PyMuPDF get_pixmap](https://...) — DPI 파라미터가 여기 있다
- `src/render.py` → `render_page()` — DPI 200이 하드코딩된 자리
- 관련: [도면-정렬-방식](./도면-정렬-방식.md)
```

날짜는 `YYYY-MM-DD`. 페이지 간 링크는 상대경로.

코드는 **심볼명으로** 가리킨다 (`render.py` → `render_page()`). 줄번호는 한 달이면 어긋난다.

원본은 포인터로 가리킨다. `.wiki/` 안에 사본을 두지 않는다. 다만 링크가 죽으면 페이지가 통째로 무가치해지는 항목에는 원문 한두 줄을 그대로 인용해 붙인다.

본문 길이에 규칙은 없다. 수준은 사용자와 주고받으며 맞춘다.

## status

`draft` → `locked` → `deprecated`. 한 방향으로만 간다.

| 값 | 뜻 | 편집 |
|---|---|---|
| `draft` | 같이 다듬는 중 | 자유 |
| `locked` | 확정 | 확인받고 |
| `deprecated` | 대체됨 | 안 함 |

- **`locked` 는 사용자가 말할 때 건다.** 먼저 확정할지 묻지 않는다 — `draft` 로 오래 머무는 페이지가 정상이다. 결정사항은 처음부터 `locked` 로 만들 수 있다.
- **`locked` 페이지에 수정 요청이 오면 `locked인데 draft로 내리고 고칠까요?` 하고 멈춘다.** 승낙하면 `draft` 로 내리고 고친다. 다시 잠그는 것도 사용자가 말할 때 한다.
- 페이지가 통째로 대체되면 `status: deprecated` 로 바꾸고 `superseded_by: ./새-페이지.md` 를 넣는다. 내용은 남겨둔다.

## 항해

페이지를 찾는 수단은 파일명과 `grep` 둘뿐이다. 인덱스 파일·태그·검색 인덱스를 만들지 않는다 — 사람이 손으로 유지해야 하는 것은 전부 썩고, 썩은 인덱스는 없는 것보다 나쁘다.
